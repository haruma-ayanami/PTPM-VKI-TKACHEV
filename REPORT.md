## Пункт В. Локализация аномалий

Все восемь упавших тестов объясняются двумя некорректными строками.

**Строка 41** — `days_needed = max(1, distance // 500)`. По правилу тарификации один день даётся за каждые полные 500 км, поэтому посылка короче 500 км должна прийти в день отправки. Разработчик обернул результат в `max(1, ...)`, и любая посылка до 500 км получила срок ровно один день. Оператор «страхует» функцию от нуля, но ломает правило для коротких расстояний: маршруты 1 км и 499 км оказываются одинаковыми по сроку.

**Строка 44** — `days_needed = days_needed // 2`. Экспресс сокращает срок вдвое. Базовый срок для 500 км равен одному дню, а `1 // 2 = 0`, то есть посылка доставляется в день отправки. Собственное ограничение «не меньше одного дня» после деления не сохраняется. Дефект заметен только на дистанциях до 999 км и полностью скрыт на больших, поэтому в исходном коде не бросается в глаза.

| № | Упавший тест | Строка | Дефект в логике разработчика | Исправление |
|---|---|---|---|---|
| 1 | `test_accepts_minimum_weight` | 41 | `max(1, ...)` задаёт минимум 1 день; при 100 км ждём день отправки | `days_needed = distance // 500` |
| 2 | `test_accepts_maximum_weight` | 41 | То же: 100 км вернули `2026-09-04` вместо `2026-09-03` | `days_needed = distance // 500` |
| 3 | `test_calculates_regular_package_cost` | 41 | То же: обычная посылка на 100 км не доставляется на следующий день | `days_needed = distance // 500` |
| 4 | `test_applies_medium_weight_coefficient` | 41 | То же: коэффициент 1.2 посчитан верно, сдвинута только дата | `days_needed = distance // 500` |
| 5 | `test_applies_heavy_weight_coefficient` | 41 | То же: коэффициент 1.5 посчитан верно, сдвинута только дата | `days_needed = distance // 500` |
| 6 | `test_adds_fragile_package_fee` | 41 | То же: надбавка 300 руб. верна, неверна дата | `days_needed = distance // 500` |
| 7 | `test_adds_dangerous_package_fee` | 41 | То же: надбавка 1000 руб. верна, неверна дата | `days_needed = distance // 500` |
| 8 | `test_express_delivery_has_at_least_one_delivery_day` | 44 | `1 // 2 = 0` дней — экспресс-доставка становится мгновенной | `days_needed = max(1, days_needed // 2)` |

## 4. Дополнительное наблюдение

Аномалия найдена при анализе кода, но **ни одним упавшим тестом не зафиксирована**, поэтому в Пункт Б не входит.

Строка 36 — `total_cost *= 0.5`: экспресс-доставка удешевляет посылку ровно вдвое, хотя экспресс-тарификация предполагает наценку за скорость. Сервис теряет деньги на каждой экспресс-посылке — вероятно, перепутаны множитель и делитель. Предлагаемая правка: `total_cost *= 1.5`.

## Приложение. Как запустить тесты

```bash
python -m unittest discover -v
```

Команда запускается из корня репозитория и находит все 51 тест. Чтобы это работало, в структуре проекта сделано три правки, не влияющие на логику расчётов:

- добавлены пустые файлы `src/__init__.py` и `tests/__init__.py`, без которых `discover` пропускает папку `tests` и сообщает `Ran 0 tests`;
- тесты импортируют модули как `from src.delivery_service import ...` и `from src.my_project import ...`;
- `src/my_project.py` читает `blacklist_login.json` по пути от файла модуля (`BASE_DIR`), поэтому не зависит от текущего каталога.

Приложение из ЛР1 запускается командой `python -m src.my_project`.

Исходный код модуля доставки не исправлялся — прогон выполнен на предоставленной версии, поэтому 8 тестов падают.
